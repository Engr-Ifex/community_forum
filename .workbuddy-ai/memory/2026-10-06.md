# Mobile UI fixes + test-data cleanup

## 1. "Browse discussions" escaped its card (Dashboard)
`Dashboard.jsx` welcome panel: the action group was
`flex shrink-0 flex-wrap gap-2`. **`flex-wrap` + a bare `shrink-0` is a
contradiction** — `shrink-0` pins the container to its max-content width, so the
wrap never triggers and the group overflows its parent. Two `md` buttons
(~343px) are wider than a phone's card interior (~312px), so the second button
was pushed out.
Fix: `flex w-full flex-col gap-2 sm:w-auto sm:flex-row sm:flex-wrap` with
`w-full justify-center sm:w-auto` on each button — a full-width stack on mobile,
side-by-side from `sm` up.

## 2. Admin tabs were cut off (Reports / Moderation log)
`Admin.jsx` used `overflow-x-auto` with `shrink-0` buttons. The tabs did scroll,
but there was no visible affordance, so the last two tabs simply looked missing.
Fix: `flex flex-wrap gap-2` and dropped `shrink-0` — all six tabs are now always
visible, wrapping to ~3 rows on a phone.

## 3. Full mobile audit — what I found and changed
- **`whitespace-pre-wrap` without `break-words`** in 7 user-content blocks
  (`DiscussionDetails`, `DiscussionCard`, `ReplyItem`, `ReportRow`, `Profile`×2,
  `AdminUsers` bio). One long unbroken string (a URL, a pasted token) overflows
  the container horizontally. Added `break-words` to all 7.
- **`Notice` (ui.jsx)** — the message `<span>` had no `min-w-0`, so a long
  unbroken string could push the dismiss button off the edge. Added
  `min-w-0 break-words`.
- **`PageHeader` (ui.jsx)** — `flex shrink-0 flex-wrap` → `flex flex-wrap
  sm:shrink-0` (the pin is only meaningful once the header is a row).
- **`AdminCategories`** — card was `flex items-start justify-between`; now
  `flex flex-col gap-3 sm:flex-row sm:items-start sm:justify-between` so the
  Edit/Delete pair sits under the text on a phone, and its button group uses
  `sm:shrink-0`.
- **`AdminUsers` user-detail modal** — Name/Email rows were `flex justify-between`
  with no wrap, so a long email overflowed the `max-w-lg` dialog. Now
  `flex flex-wrap items-baseline justify-between gap-x-4 gap-y-1` with
  `min-w-0 break-words text-right` on the value.

**Checked and found already correct** (no change needed): every grid is
mobile-first (`grid-cols-1` base + breakpoints); all 3 admin `<table>`s sit in an
`overflow-x-auto` wrapper; `RecentDiscussionCard` / `CategoryTile` / `CategoryCard`
already use `min-w-0` + `truncate`; the Moderation filter row, `ReportRow` chips
and action rows all use `flex-wrap`; `AvatarMenu` already has
`max-w-[calc(100vw-2rem)]`.

## New guard: `client/scripts/verify-responsive.mjs`
Static source analysis (no DOM) with 5 rules, each tied to a real bug class:
1. no `flex-wrap` + **bare** `shrink-0` on the same element;
2. the Admin tab strip wraps and is not an `overflow-x-auto` scroller;
3. no bare multi-column `grid-cols-2+` (mobile-first enforced; `grid-cols-1` is
   allowed as the explicit base);
4. every `whitespace-pre-wrap` block also carries `break-words`;
5. each `<table>` has an `overflow-x-auto` ancestor.
It **strips comments** (block + line) before scanning — comments legitimately
mention the banned classes, and the first version flagged its own documentation.
It found the `AdminCategories` and `PageHeader` contradictions on its first real
run, so it is not merely decorative.
