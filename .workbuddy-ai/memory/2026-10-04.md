## Phase 13 — Repairing the client after a bad merge (`d0e7031`)

### Symptom
`npm run lint` went from 0 errors to **5 errors** and the file count from 70 to
76; `npm run build` died with
`[UNRESOLVED_IMPORT] Could not resolve './components/Discussions/DiscussionDetail'`.

### Cause
The teammate's merge `d0e7031 Merge branch 'IFE' … into IFE` resolved conflicts
badly: for every file both sides touched, git kept **my** version but spliced in
fragments from **their** branch, leaving references to state, handlers and
components that were never declared. It was committed in that state.

### Diagnosis that made it fast
Compare the merge against **both** parents:
- `git diff <merge>^1 <merge> -- <file>` → distance from my side
- `git diff <merge>^2 <merge> -- <file>` → distance from theirs
- `git diff --stat <merge>^1 <merge> -- client/` → the whole blast radius at once

Every damaged file was a few lines from mine and hundreds from theirs → "my file
with their fragments pasted in". That told me reverting was the right fix.

### Damage found
| File | Damage |
| --- | --- |
| `App.jsx` | 3 unused imports; `./components/Discussions/DiscussionDetail` **does not exist** → build dead |
| `Discussions/Discussions.jsx` | state block swapped out (`categories`/`discussions`/`totalPages` deleted) while the body still used them; `handleCategoryChange`/`handleSortChange` replaced by a `handleBack` referencing 4 undeclared setters + undefined `navigate`; `</div></form>` → `</header>)}` |
| `CreateDiscussion.jsx` | duplicate `const [category, setCategory] = useState("")` |
| `CategoryCard.jsx` | duplicate `};` |
| `DiscussionDetails.jsx` | `<ReplyForm onReply={onReply}/>` added, never imported, `onReply` undefined |
| `client/.env.example` | **`VITE_USER_PASSWORD` / `VITE_MODERATOR_PASSWORD` / `VITE_ADMIN_PASSWORD` added** |
| `client/.gitignore` | stray literal `gitignore` line + redundant `.env` block |
| `DiscussionCard.jsx`, `Moderation.jsx`, `Profile.jsx` | `};`→`}`, trailing newline stripped |

The `.env.example` change was the most dangerous: `VITE_`-prefixed vars are
inlined into the browser bundle, so those names invite shipping real credentials
to every visitor.

### Fix
`git checkout d0e7031^1 -- <each damaged file>` — revert to the last verified
state. The merge fragments were internally inconsistent, so reverting was
strictly safer than patching forward. Also cleaned 3 warnings in my own
`client/scripts/verify-render.mjs` (unused `createContext` import, dead
`OVERRIDES` const, `aliases` param used only in recursion) → lint baseline
dropped 22 → **20**.

**Nothing outside `client/` was touched by the merge** — `server/`, `docs/`,
`README.md`, root `.gitignore` all show an empty `git diff --stat`.

### Verification (all actually run)
- `npm run build` → ✓ **142 modules**, 470.87 kB JS / 132.99 kB gzip, 40.17 kB CSS
- `npm run lint` → **0 errors, 20 warnings** (advisory baseline only)
- `verify-routes` / `verify-shells` / `verify-ui` / `verify-render` → **ALL PASSED**
- All internal `to=` / `navigate()` targets map to declared routes (no dead links)
- All orphan files' own imports resolve (no latent import errors)

### Reported, then deleted with the user's approval — 6 unreferenced files
Nothing imported them, so they didn't break the build, but four contradicted
documented project rules:
- `Profile/UserData.jsx` + `Categories/CategoryData.jsx` — hardcoded **mock data**
- `Profile/Users.jsx` — read/wrote **`localStorage`** as a user store
  (violates convention 3)
- `Moderation/ReportButton.jsx` — a **second** report implementation (violates
  the "one shared report dialog" rule; `Reports/ReportDialog.jsx` is the one)
- `Profile/PublicProfile.jsx` — mock-data-driven profile keyed on `:username`
- `Discussions/ReplyForm.jsx` — benign, clean, just unused

The user chose **delete**. Removed all six with plain `rm -f` (never recursive).
Final state: build 142 modules, lint **0 errors / 19 warnings** on **70 files** —
i.e. *cleaner than the pre-merge baseline of 22 warnings*, because 3 warnings in
my own `verify-render.mjs` were cleaned up at the same time.
